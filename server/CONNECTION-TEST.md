# Проверка связи ДО переноса данных

Экспорт приостановлен. Текущий рабочий URL мини-аппа и backend-config.js не меняем, Supabase не удаляем. Локальная пустая схема уже установлена. Тест не создаёт пользователей/брони и не отправляет игровые команды.

## Что проверяет отдельная страница

https://tengizka.github.io/1shot/local-check.html

- GitHub отдаёт HTML/JS, а браузер обращается к `https://api.tengizka.fun` напрямую.
- `/healthz` подтверждает локальный backend и версию схемы PostgreSQL.
- `capabilities` и `hosts` проверяют чтение реальных локальных таблиц. Ноль ПК и выключенные брони на пустой базе — допустимы, это не имитация данных.
- Запрос списка броней без подписи должен получить 403, административный маршрут на публичном порту — 404.
- При запуске как Telegram Web App отдельная кнопка отправляет initData только на фиксированный адрес сервера. `list` проверяет подпись и возвращает только список пользователя, ничего не записывает. Это ещё не проверка входа в Gizmo.
- Ручной минутный тест повторяет чтение раз в 5 секунд. Нет WebSocket/SSE. При скрытии страницы тест останавливается. До нажатия кнопок API-запросов нет.

## Подготовка

1. Docker работает; на компьютере `/healthz` по http://127.0.0.1:8787 возвращает ok. Старый Desk закрыт; не направлять его на новую базу.
2. В существующую папку server положить `Enable-GitHub-Test.ps1` и запустить:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\Enable-GitHub-Test.ps1
   ```

   Добавляется только разрешённый Origin `https://tengizka.github.io` в ALLOWED_ORIGINS, остальные настройки сохраняются. Пересоздаётся только контейнер API с тем же образом, без сборки и миграций. Пауза API на несколько секунд ожидаема. Пароли/база/Desk не меняются. Скрипт не настраивает туннель.
3. Настроить отдельный Cloudflare Tunnel для `api.tengizka.fun` → `http://localhost:8787`. cloudflared запускается на Windows-хосте. Нельзя публиковать 8788, PostgreSQL или Gizmo. Не запускать старый туннель с маршрутом gizmo.tengizka.fun → внутренний Gizmo. Если коннектор уже установлен, проверить, какой туннель/маршруты он запустит, а не ставить второй вслепую. Токен вводить только локально, не в чат.
4. DNS домена должен быть активен в Cloudflare. С телефона через мобильный интернет открыть `https://api.tengizka.fun/healthz`. Пока нет ok — не менять Telegram URL.
5. Открыть отдельную страницу теста с GitHub. Проверить связь и минутный тест. Отличить проблему туннеля/DNS от CORS: если healthz напрямую работает, а запросы из GitHub не проходят, проверить ALLOWED_ORIGINS.
6. Для проверки Telegram временно указать в меню Web App бота **отдельную тестовую страницу**. Сохранить старый URL меню для возврата. Открыть через кнопку мини-аппа, а не обычную ссылку; выполнить проверку сервера и нажать «Проверить Telegram». Не вводить AGENT_SECRET или пароль на веб-странице.

## Что это НЕ доказывает

Тест не подтверждает регистрацию, баланс, реальный login/logout, работу блокировок, восстановление после Windows reboot или качество сети весь день. После прохождения связи отдельно подключаем один Desk, один тестовый аккаунт и свободный ПК, проверяем защиту занятого ПК, брони и отмену. Не включать два агента на разных базах для одних компьютеров.

Чистый старт возможен: заново создать облачные таблицы не требуется, локальная схема уже есть. В новой базе нет 28 перенесённых Telegram-привязок и старой истории, нужно снова связать пользователя с аккаунтом клуба. Аккаунты, балансы и игровые сессии в Gizmo не удаляются. Старую Supabase сохраняем как архив до явного решения. Для чистого старта отдельно согласовать журнал Desk и event_cursor: не удалять SQLite вслепую и не продолжать старый курсор событий в пустой базе.

После приёмки GitHub-версию можно переключить на локальный API изменением backend-config.js и сохранением точного CORS-origin. При выключенном ПК страница с GitHub может открыться, но локальные данные и действия будут недоступны. Туннель остаётся внешней зависимостью. Нельзя обещать бесперебойную работу без проверки на сетях клуба и посетителей.
