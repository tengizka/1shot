# 1SHOT Local — первый проверочный выпуск

Локальный API + PostgreSQL. **Во время работы не обращается к Supabase, не использует его SDK, Auth, PostgREST или Edge Runtime.** Cloudflare нужен только как туннель до телефонов. Desk, клубный API и база остаются внутри клуба. Старые облачные исходники оставлены для отката и как версия SQL-миграций; это не облачная зависимость локального процесса.

Это ещё не выполненный перенос клуба: данные, настройки Windows, домен и туннель автоматически не переключаются. Пятисекундный опрос сохранён; событийное обновление пока не реализовано. Снижается сетевой путь Desk → API, но фактическое ускорение надо измерить в клубе.

## Состав и границы

- PostgreSQL 17 в отдельном Docker volume; порт БД **не опубликован**.
- API на Deno, прямые параметризованные SQL-запросы, прежние транзакции и проверки владения/lease.
- `http://127.0.0.1:8787` — мини-апп и публичный API `/api`; только этот порт можно направлять в туннель.
- `http://127.0.0.1:8788/api` — служебный API Desk; требуется `AGENT_SECRET`. **Не публиковать через туннель.**
- Административные маршруты вообще отсутствуют на публичном порту; claim/finish авторизации также запрещены публично, даже с секретом.
- Проверка подписи/возраста Telegram initData, шифрование краткоживущих запросов пароля, разделение пользовательских данных сохранены. CORS, ограничение тела 64 KiB и ограничитель частоты — дополнительная защита, не замена подписи.
- Gizmo обслуживает только Desk. Контейнеры не получают Gizmo-пароли. Нет выключения ПК или принудительного завершения чужих игр.

## 1. Подготовка Windows — пока не переключать клуб

Нужен поддерживаемый Docker Desktop для Windows с **WSL2 / Linux containers**, аппаратная виртуализация и свободные ресурсы. Учтите лицензию Docker Desktop для вашей организации. На слабом/загруженном ПК сначала измерьте расход памяти. Не устанавливайте обновления с перезагрузкой посреди смены.

1. Сохранить копии `%LOCALAPPDATA%\1SHOT Desk\.env` и `desk.sqlite3` в защищённом месте. SQLite копировать при полностью завершённом Desk, а не после сворачивания крестиком.
2. Установить Docker Desktop с официального сайта, включить WSL2 по его инструкции, запустить. При необходимости перезагрузку согласовать со сменой.
3. Скачать **обновлённые исходники целиком**. Не переносить одну папку `server`: сборке нужны файлы мини-аппа и SQL из соседних папок.
4. Открыть PowerShell в папке `server` и выполнить:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\Setup.ps1
   ```

5. Скрипт спросит **существующий AGENT_SECRET из Desk** и **существующий Telegram bot token**. Ввод скрыт. Вводить только на своём ПК — не в чат. Пароли БД генерируются автоматически. Настройки сохраняются в `server/.env` с ограниченным Windows ACL.
6. Открыть `http://127.0.0.1:8787/healthz`: ожидается `{"ok":true,"backend":"local"}`. Мини-апп доступен по `http://127.0.0.1:8787/`, но вход требует настоящего Telegram initData, а бронирование пока отключено.

**Здесь остановиться до переноса данных. Не менять существующий Desk, не включать старый туннель.** Установленная база пустая, рабочие данные не подгружаются автоматически.

Скрипт не устанавливает Docker, не меняет брандмауэр, не настраивает домен, не включает бронирование и не подключается к Supabase. Повторный запуск использует существующий `.env`/volume. Никогда не выполнять `docker compose down -v` на рабочей системе: `-v` удаляет базу.

## 2. Перенос данных — отдельное окно обслуживания

Перенос рассчитан на текущую облачную схему 006–012, не на произвольные старые версии. Источник **только читается**. Для экспорта нужен PostgreSQL connection string Supabase, не anon/service key. Взять его в панели проекта; при недоступном IPv6 использовать подходящий session pooler. URL с паролем хранить только локально. TLS для источника обязателен (`sslmode=verify-full` с доверенным сертификатом; не отключать проверку сертификата).

1. Запланировать обслуживание. Завершить/проверить незавершённые команды и запросы входа. Не повторять неизвестные операции.
2. Закрыть запись через старые публичные функции на период переноса: например, временно заменить **только в старом облачном проекте** `TELEGRAM_BOT_TOKEN` на отдельное случайное значение обслуживания, сохранив исходный токен локально для отката. Это делает старые подписи посетителей недействительными; **сам токен у BotFather не отзывать**. Локальный сервер должен использовать настоящий токен. Проверить отказ старого `club-bookings/state` с реальным initData до экспорта. Не оставлять две публичные системы принимающими изменения.
3. Полностью остановить старый Desk. Подождать минимум 30 секунд до истечения lease. Сохранить `.env`/SQLite. Приложение также проверит lease при экспорте; queued/running команд и pending/running запросов входа быть не должно. Дождаться истечения запросов и штатной очистки **до остановки Desk**, если они есть. Нельзя просто удалять/помечать неизвестные команды выполненными ради экспорта.
4. Установить Deno 2 для запуска инструмента переноса (или использовать контейнер Deno). В `server/private/transfer.env` сохранить локально:

   ```dotenv
   SOURCE_DATABASE_URL=postgresql://...адрес_источника_с_TLS...
   ```

   Эта папка игнорируется Git и Docker. Не присылать файл. Из корня исходников:

   ```powershell
   deno run --env-file=server/private/transfer.env --allow-net --allow-env --allow-read --allow-write server/tools/transfer.ts export server/private/club-export.json
   ```

5. Проверить наличие JSON и `.sha256`. Экспорт содержит персональные данные; хранить в защищённом месте. Сделать независимую полную резервную копию источника его средствами. Не удалять облачный проект.
6. Импорт запускается внутри локального API-контейнера, чтобы **не открывать порт БД**. Создать локально файл `server/private/import.env`:

   ```dotenv
   LOCAL_ADMIN_DATABASE_URL=postgres://oneshot_owner:ПАРОЛЬ_POSTGRES_PASSWORD_ИЗ_SERVER_ENV@db:5432/oneshot
   CONFIRM_LOCAL_IMPORT=YES
   ```

   Из папки `server`:

   ```powershell
   docker compose run --rm --no-deps -v "${PWD}/private:/transfer:ro" api run --env-file=/transfer/import.env --allow-net --allow-env --allow-read tools/transfer.ts import /transfer/club-export.json
   ```

   Импорт идёт одной транзакцией, проверяет количество строк и отказывается перезаписывать непустую базу. **Не очищать непустую базу, чтобы заставить его пройти.** При ошибке — разбор причины, не удаление данных.

Переносятся profiles, hosts_cache, reservations, club_settings, club_bookings, club_events, club_accounts, club_commands, club_auth_requests. Сохраняются ID и связи. Worker lease не переносится; свежесть ПК обнуляется; бронирование остаётся выключенным. Журнал владения блокировками остаётся в том же Desk SQLite — его нельзя удалять. Дополнительные столбцы источника, которых нет в локальной схеме, остаются в JSON-архиве; инструмент перечислит их. До переключения проверить эти предупреждения — это не обещание переноса неизвестных расширений схемы.

## 3. Контролируемое переключение

1. Нужен новый Desk с поддержкой `CLUB_API_URL` (1.7.0-alpha). В существующий локальный `.env` добавить:

   ```dotenv
   CLUB_API_URL=http://127.0.0.1:8788/api
   ```

   Старый `SUPABASE_URL` можно оставить для осознанного отката; локальный адрес имеет приоритет, автоматического переключения в облако **нет**. `LEGACY_AUTH_ENABLED` должен быть выключен. Старые plaintext auth/reservations endpoints локально не поддерживаются.
2. Запустить **один** Desk, сверить ПК и журнал собственных блокировок. Отсутствие свежих данных не разрешает вход. При активных бронях/неизвестных блокировках перенос принимать индивидуально, без насильственного снятия блокировок.
3. Включить бронирование только после проверки:

   ```powershell
   docker compose exec -T db psql -U oneshot_owner -d oneshot -c "update public.club_settings set enabled=true,flow_version=2 where id=true;"
   ```

4. Удалить/отключить старый ненужный маршрут `gizmo.tengizka.fun` **перед запуском коннектора**, либо использовать отдельный новый туннель без него. Старый маршрут не должен внезапно открыть внутренний сервис.
5. Для нового маршрута Cloudflare: hostname **api.tengizka.fun**, service **HTTP → localhost:8787**. `cloudflared` устанавливается на Windows-хост, не в контейнер. Токен туннеля вводить только локально. Не направлять туннель на 8788, 5432 или API клубной системы. Здесь localhost означает компьютер с cloudflared, а не телефон.
6. Проверить `https://api.tengizka.fun/healthz` с мобильного интернета. Проверить, что `/api/club-agent` и `/api/club-desk` снаружи дают 404. Убедиться, что DNS домена в Cloudflare активен; не считать это установленным по существованию туннеля.
7. Изменить Web App URL у Telegram-бота на **https://api.tengizka.fun/**. Локальный сервер раздаёт мини-апп с same-origin `/api`, без облачного адреса. Переоткрыть Telegram. GitHub Pages остаётся прежним вариантом для отката; посетителей перевести на новый URL.
8. Проверить на тестовом аккаунте: вход/регистрацию, собственные данные и баланс, ручную бронь без имени, полночь, отмену без завершения игры, смену пароля с подтверждением. Отказ занятому ПК, перенос активного аккаунта запрещён. Проверить отсутствие обращений к домену Supabase в Network.

Не запускать два Desk на разных базах: их leases независимы и не защищают от двойного управления одними ПК. Облачную запись держать закрытой. После приёмки источник можно приостановить, но не удалять до проверки резервных копий и согласования срока хранения.

## 4. Резервное копирование и запуск после перезагрузки

Из папки `server`: `powershell -NoProfile -ExecutionPolicy Bypass -File .\Backup.ps1`. Получается бинарный `pg_dump -Fc` в `server/backups`; PowerShell не перенаправляет бинарный поток в текстовый файл. Архив содержит персональные данные; ограничить доступ, включить шифрование диска и копировать на другое устройство. Копия на том же диске не спасёт от его отказа. Сделать регулярное задание Планировщика Windows и проверить результат. Автоматическое расписание пока не устанавливается.

Для проверки восстановления используйте **отдельную тестовую базу**, не рабочую. Пример в контейнере после копирования архива в `/tmp/check.dump`:

```powershell
docker compose exec -T db createdb -U oneshot_owner oneshot_restore_check
docker compose exec -T db pg_restore -U oneshot_owner -d oneshot_restore_check --exit-on-error /tmp/check.dump
docker compose exec -T db psql -U oneshot_owner -d oneshot_restore_check -c "select count(*) from profiles; select count(*) from club_bookings;"
```

Сверить количества с исходной базой и проверить связи; не направлять рабочий Desk на эту копию. Восстановление на рабочую базу — отдельная процедура обслуживания.

Контейнеры имеют `restart: unless-stopped`, но **Docker Desktop должен запуститься**. Настроить запуск Docker при входе в Windows; это не гарантия работы до входа пользователя. Проверить реальную перезагрузку, запуск Docker, cloudflared и одного Desk. Туннель можно установить как службу штатной командой Cloudflare. Для полностью безоператорного запуска до Windows logon потребуется другой способ размещения/служба — этот preview его не обещает.

Если компьютер выключен, диск заполнен или пропал интернет, мини-апп не сможет создавать новые брони. HTTPS-туннель и доступность Cloudflare проверить на сетях ваших посетителей; отсутствие настройки роутера не гарантирует доступность на любом провайдере.

## Откат

До появления новых операций в локальной базе: остановить новый Desk, вернуть его сохранённую конфигурацию, восстановить настоящий Telegram token в старом облачном проекте и старый Web App URL. Сохранить локальную базу и журналы для разбора.

**После новых локальных операций простой возврат на старую базу небезопасен**: нужна сверка броней, аккаунтов, команд и SQLite. Автоматический двусторонний sync/merge не реализован. Не считать перенос с нулевым простоем или автоматическим откатом.

## Проверки разработки

`deno check server/main.ts server/tools/transfer.ts`; `deno test -A server/tests/ tests/*.test.ts`; Python tests; workflow `Test local server` собирает реальные контейнеры PostgreSQL/API и проверяет изоляцию портов, lease, запись и сохранность после перезапуска. Тесты не подключаются к реальным ПК клуба. Живые данные и права API ещё требуют приёмки на месте.
