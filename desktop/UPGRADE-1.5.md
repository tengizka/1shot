# 1.5.0-beta — экономный обмен для Supabase Free

## Установка: порядок обязателен

GitHub Pages не обновляет Supabase и Windows. Предполагается работающая версия 1.4 и миграции 006–010.

1. Получить свежие исходники. В Supabase **SQL Editor** выполнить целиком `supabase/migrations/202609250011_economy_poll.sql`.
2. Из папки исходников в CMD / PowerShell:

   ```cmd
   npx.cmd supabase functions deploy club-agent --project-ref zqhfvtgktbfnxcclqqny --no-verify-jwt --use-api
   npx.cmd supabase functions deploy club-bookings --project-ref zqhfvtgktbfnxcclqqny --no-verify-jwt --use-api
   ```

3. Полностью завершить старый Desk через «Выход». Распаковать **весь** архив 1.5 в новую папку. Сохранить `%LOCALAPPDATA%\1SHOT Desk\.env` и `desk.sqlite3`. Запустить только один агент.
4. Переоткрыть мини-апп: в профиле `version 1.5.0`. В Desk должна быть версия `1.5.0-beta`, обе связи активны. SQL-проверка worker: `select protocol, lease_until > now() as online from club_worker where id=true;` — ожидаются `2`, `true`.

Новый Desk требует новый серверный пакет. Если сервер старый, он останавливает обработку и показывает ошибку, а не скрытно возвращается к частым запросам. Старые серверные действия сохранены для отката. До обновления `club-bookings` мини-апп использует совместимый раздельный опрос с более длинными интервалами.

## Что экономится

- Desk: один `club-agent/snapshot` каждые **10 секунд** в спокойном режиме. Внутри один SQL RPC: продление lease, состояния ПК, активные брони/события, запросы на аккаунты и команды. Статусы ПК собираются локально каждые 5 секунд — это не обращения к Supabase.
- Результаты чтения баланса/профиля идут со следующим пакетом, без отдельного Edge-вызова на каждый аккаунт. Метка времени отражает момент получения данных: повторная отправка старого кэша не делает его свежим.
- Очередь авторизации запрашивается отдельно только при наличии pending-заявок. Проверка пароля/регистрация и подтверждения результатов остаются отдельными защищёнными операциями.
- Старый plaintext-маршрут `pending-auth` по умолчанию не опрашивается. Только если действительно остались старые клиенты, можно временно добавить `LEGACY_AUTH_ENABLED=true` в локальный `.env`: проверка будет раз в минуту. Не включать без необходимости. Современная авторизация не требует этой настройки.
- Мини-апп объединяет карту, брони, аккаунт и результаты команд в один запрос каждые **15 секунд**. Нет отдельного постоянного опроса для каждого блока и нет выдачи завершённой истории в новом пакете.
- При скрытой вкладке/мини-аппе сетевой опрос прекращается, при возвращении отправляется один свежий запрос. Это зависит от события видимости, которое передаёт браузер Telegram.
- После действий кратковременно ускоряется обновление. Desk — до 2 секунд для переходных состояний, максимум 30 секунд на неизменное состояние; мини-апп — до 5 секунд на 30 секунд после действия. Зависшая команда не оставляет вечный быстрый опрос.
- Ошибки транспорта замедляют опрос до 60 секунд. Неизвестные изменяющие операции не повторяются вслепую.

## Бюджет вызовов: расчёт, а не обещание тарифа

Для спокойного режима, без ошибок, действий, запусков и дополнительных клиентов:

| Источник | Вызовы |
|---|---:|
| Один Desk 24/7, 30 дней | 259 200 |
| Один Desk 24/7, 31 день | 267 840 |
| Один открытый мини-апп, 1 час | около 240 |
| Скрытый мини-апп | 0 периодических вызовов |

Пример: 100 посещений мини-аппа в день по 10 минут за 31 день — около 124 000 периодических клиентских вызовов. Вместе с Desk — **391 840**. Авторизация, создание/отмена броней, ручные действия, ускоренные опросы, первоначальные загрузки и другие проекты организации расходуют квоту дополнительно. Постоянно открытые мини-аппы тоже учитываются.

При квоте 500 000 после фонового Desk за 31 день остаётся 232 160 вызовов — не вся эта сумма доступна только фоновым клиентам. Не гарантируется работа в Free при произвольной посещаемости или атаках. Не выключаем при достижении порога обработку существующих броней: это нарушило бы снятие собственных блокировок.

Объём логов/трафика нельзя точно вывести из числа вызовов. Объединение SQL в один RPC также уменьшает количество обращений к PostgREST. Не отключены важные ошибки, аудит или защитные проверки. Накопленный расход текущего периода не обнуляется после обновления.

## Задержки и безопасность

Новые команды обычно подхватываются в следующем 10-секундном цикле плюс время сети/сервера. Это осознанный компромисс Free; «Войти сейчас» не означает нулевую задержку. Подтверждение сессии может прийти следующим ускоренным циклом.

Lease остался 30 секунд на сервере; агент использует консервативные 25 секунд и прежний 10-секундный запас перед опасными действиями. Свежесть ПК, проверки сессии, запрет повторного неизвестного login, прямой вход без lock/unlock и журнал собственных блокировок сохранены. При просрочке данных карта становится недоступной для нового входа, а не изображает ПК свободным. Сервер повторно проверяет условия; Gizmo по-прежнему не предоставляет атомарный compare-and-login.

Новые RPC доступны только `service_role`, не `anon`/`authenticated`. Клиентский RPC вызывается после проверки подписи Telegram и возвращает только данные этого пользователя. Серверный ключ и секрет агента не добавлялись в мини-апп. Общий пакет не содержит паролей или шифротекста авторизации.

## Приёмка и контроль

1. Проверить вход на свободный ПК, отказ занятому, scheduled, отмену без завершения игры, logout только своей сессии, смену пароля и регистрацию тестового гостя.
2. При обрыве облака/связи с локальным сервером старые статусы не должны получать новую метку свежести. После перезапуска не должен повторяться неизвестный вход.
3. В Network открытого мини-аппа после загрузки — один `club-bookings` с `action=state` примерно раз в 15 секунд; в скрытом состоянии — нет периодических запросов. Не публиковать Network-дампы с Telegram initData.
4. Записать расход в Supabase Usage и даты расчётного периода, затем сравнить через 24 часа с аналогичной нагрузкой: Edge Function Invocations, Log Ingestion, Egress, Database Size. Для одного простаивающего Desk ориентир — 8640 вызовов/сутки плюс реальные операции.
5. Оставить запас квоты на оставшиеся дни и другие проекты организации. Логи ограничены сроком хранения; счётчик Usage — источник месячного расхода.

Ротация секретов, настройки тарифа/логирования Supabase и живой сервер клуба этим коммитом не изменялись. Старые брони, журнал SQLite и история заявок на пароль не удаляются. Очистка auth-запросов старше суток сохраняет существующее поведение 009.
