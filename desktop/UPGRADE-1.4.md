# Обновление 1.3 → 1.4.0-beta

## Что изменилось

- **Новый мгновенный вход — напрямую, без lock/unlock.** Агент повторно проверяет свободный ПК, отсутствие чужой/другой сессии и действующий lease, сохраняет намерение входа до POST. Неизвестный результат не повторяется: агент сверяет сессию. Уведомлений о бронировании для instant нет. Настоящие брони «Сегодня к…» по-прежнему блокируют только свободный ПК и уведомляют администратора. Native reservations Gizmo не создаются.
- Старые технические блокировки из 1.3 обрабатываются по сохранённому журналу; их нельзя безопасно игнорировать, удалять SQLite или снимать все замки подряд. Новый путь не создаёт технический замок. Gizmo не предоставляет атомарный compare-and-login: остаётся короткое окно гонки с ручным входом через Manager.
- **«Запросы на сброс» в Desk:** «Сменить пароль» выбирает аккаунт по Gizmo ID выбранной заявки. После проверки личности администратор вводит новый пароль; Desk меняет и проверяет его в Gizmo. «Услуга предоставлена» — отдельное ручное подтверждение уже оказанной услуги, **не смена пароля**. «Закрыть без выполнения» закрывает заявку без изменения пароля. Завершённые заявки исчезают из ожидающих, но не стираются из БД.
- Мини-апп показывает результат последней заявки на пароль отдельно от прочих команд. Синхронизация при потере облака повторяет **только результат**, не смену пароля. Если Desk пишет, что результат неизвестен, проверяйте аккаунт вручную; если пароль уже проверен и ожидается синхронизация — не меняйте его повторно. Пароли не сохраняются в журнале и не передаются в Supabase.
- Сверху зала появился заметный баннер **«Моя сессия»**: ПК, сведения, завершение. Самопроизвольного открытия окна сессии нет. Устаревшие данные помечаются, завершение по ним недоступно.
- Баннер «Мои брони» из профиля удалён. Собственная бронь подсвечена синим; нажатие на ПК открывает именно её сведения и отмену, в том числе при недоступном статусе ПК. Отмена не завершает игру.
- Физические зоны отделены всегда. Четыре страницы: VIP 10+20, STANDARD 100, STANDARD 200, STANDARD 300+400. Группы не разрываются между страницами; свайпы и стрелки сохранены, карта без прокрутки.
- Пять букв исходного SVG плавно мигают по отдельности внутри логотипа. Нативная подсветка тапа и выделение отключены; клавиатурный фокус сохранён. У занятого ПК — шесть SVG-рук, восемь фраз и восемь подписей кнопки, без повторения предыдущего текста.

## Установка

Предполагается установленная 1.3: миграции 006–010, актуальный `club-agent`, `enabled=true`, `flow_version=2`. Для перехода с более старой версии сначала выполнить инструкции 1.1–1.3. **Новой SQL-миграции в 1.4 нет.** Настоящее состояние сервера клуба здесь не проверено.

1. Получить свежие исходники этой ветки. Из папки исходников, например `C:\1shot-source`, выполнить в CMD / PowerShell:

   ```cmd
   npx.cmd supabase functions deploy club-desk --project-ref zqhfvtgktbfnxcclqqny --no-verify-jwt --use-api
   npx.cmd supabase functions deploy club-bookings --project-ref zqhfvtgktbfnxcclqqny --no-verify-jwt --use-api
   ```

   Обновить **обе** функции. Секреты, группы и настройки не менять. GitHub Pages не обновляет Supabase.
2. Штатно завершить старый Desk через полный выход. Сохранить `%LOCALAPPDATA%\1SHOT Desk\.env` и `desk.sqlite3`. Распаковать **весь** новый архив в новую папку, запустить один экземпляр Desk 1.4; проверить связи Gizmo/Supabase. Не запускать одновременно старый агент.
3. Переоткрыть мини-апп Telegram: внизу профиля `version 1.4.0`.

Для диагностики worker в SQL Editor:

```sql
select protocol, lease_until, lease_until > now() as online
from public.club_worker where id = true;
```

Ожидаются `protocol=2`, `online=true`. Не выключать `enabled` для обновления и не удалять локальный журнал.

## Приёмка в клубе

- На свободном тестовом ПК: instant без lock/unlock и уведомления; повтор запроса/перезапуск агента не должен повторить неизвестный вход. На занятом/чужом заблокированном ПК — отказ, без выхода игрока. Обычная бронь должна уведомлять.
- Создать заявку на пароль в мини-аппе, выбрать её в Desk, проверить личность и сменить пароль тестового гостя. Проверить исчезновение из ожидающих и результат в мини-аппе. Отдельно проверить ручную отметку и закрытие без выполнения; второе не должно означать «услуга предоставлена».
- Проверить верхний баннер сессии, завершение с подтверждением, синюю бронь и отмену через ПК. Сверить четыре страницы с физическими зонами.
- На реальном iPhone проверить анимацию отдельных букв без синего прямоугольника, новые реплики, свайпы и компактные экраны. Проверить tray и звук на Windows.

Автотесты работают на заглушках Gizmo/HTTP, локальном PostgreSQL-движке и headless Chromium. Они не заменяют проверку живого Gizmo, Windows клуба и iPhone. Группа «Клиенты» должна быть подтверждена по фактическому ID; `3` остаётся настройкой по умолчанию, не доказанным ID клуба.
