# 1SHOT Desk — Windows beta

Это **новая** система: собственные заявки в Supabase и административные
блокировки Gizmo. Native reservations НЕ создаются. Старый `agent.py`
остаётся в репозитории для работающей старой системы и отката.

## Что сделано / что ещё нужно проверить

Реализованы две брони, расписание на сегодня (МСК), автоожидание свободного ПК,
самостоятельный check-in, журнал операций SQLite, одиночный управляющий агент,
трей, Windows-звук каждые 8 секунд до подтверждения, тест звука и пауза на 5 минут.
На новое событие также отправляется системное уведомление.

Локальные mock-тесты покрывают контроллер и UI; PostgreSQL-тесты — ограничения
и доступ. **Нет доступа к живому Gizmo/Supabase клуба; блокировки, modifiedTime,
login, Windows-интерфейс на компьютере клуба, трей и слышимость требуют приёмки на месте.**
Это не Windows Service: приложение работает в пользовательской сессии Windows.
Выход из Windows, сон, выключение компьютера или пункт «Выход» останавливают агент.
Закрытие крестиком — только скрывает окно в трей, агент продолжает работать.

## Установка Windows 10/11

1. Дополнительная установка Python, .NET или WebView2 не нужна: новый интерфейс
   использует поставляемый вместе с приложением Qt WebEngine (PySide6).
2. Сборка: GitHub Actions → **Build Windows Desk** → Run workflow, выбрать ветку
   `arena/01a0d663-1shot`. Скачать артефакт `1SHOT-Desk-Windows` и распаковать
   **целиком**, не только EXE. Альтернатива: Python 3.12, в PowerShell
   `powershell -ExecutionPolicy Bypass -File desktop/build.ps1` из репозитория.
3. Создайте `%LOCALAPPDATA%\1SHOT Desk\.env` по `desktop/env.example`.
   Впишите существующие Gizmo URL (`.../api`), login/password, Supabase URL,
   `AGENT_SECRET`. Не отправляйте значения в чат и не коммитьте файл.
   Сертификат Gizmo должен быть доверенным. `GIZMO_VERIFY_SSL=false` допустим
   только как осознанный временный компромисс в доверенной локальной сети.
4. Запуск: `1SHOT-Desk.exe`. Для разработки: `pip install -r desktop/requirements.txt`,
   затем `python -m desktop.app` из корня репозитория.
5. Нажмите «Проверить звук». Настройте громкость/динамики Windows вручную:
   приложение не снимает системный mute и не повышает системную громкость.
6. По желанию добавьте ярлык EXE в `shell:startup`, отключите сон служебного ПК.
   При перезагрузке агент восстановится только после входа в Windows и запуска.

Конфигурация, журнал и звук: `%LOCALAPPDATA%\1SHOT Desk\`.
**Не удалять `desk.sqlite3` и не переносить работающий агент без журнала.**
Файл содержит коды присутствия и идентификаторы операций, защищайте его правами
Windows и резервной копией. В EXE нет встроенных секретов из старого `agent.py`.
Нельзя запускать несколько экземпляров или держать старый агент одновременно
с новым: старые очереди авторизации не имеют распределённого claim.

## Supabase / безопасное переключение

Сначала резервная копия базы. Миграции 001–005 существующей системы должны быть
применены, включая исправление profiles FK. Нужны действующие `sync-hosts`,
`pending-auth`, `upsert-profile` и `hosts`: новый агент использует их существующий
контракт. Первые две функции уже работают в клубе, но их исходников в репозитории
нет — перенос в новый Supabase без них не поддерживается.

1. Выполните `supabase/migrations/202609250006_club_desk_beta.sql` в SQL Editor.
   Она создаёт таблицы с RLS и закрытыми правами; `club_settings.enabled=false`.
   Сайт и старые брони продолжают работать по-старому.
2. Разверните функции `club-bookings`, `club-agent` вместе с `_shared/club.ts`:
   `supabase functions deploy club-bookings --no-verify-jwt` и аналогично `club-agent`.
   Проверка Telegram выполняется внутри первой функции; `AGENT_SECRET` — внутри
   второй. Секреты: `TELEGRAM_BOT_TOKEN`, существующий `AGENT_SECRET`, стандартные
   `SUPABASE_URL`/`SUPABASE_SERVICE_ROLE_KEY`. Service role никогда не отдаётся UI.
3. Выделите техническое окно. До запуска нового агента установите:
   ```sql
   update public.club_settings set enabled=true where id=true;
   ```
   Старый endpoint перестанет принимать новые брони; новый пока отклоняет их,
   потому что нет lease панели. Дайте завершиться всем старым заявкам и native
   reservations, проверьте реальное состояние ПК. Не удаляйте старые брони вслепую.
4. Остановите старый агент, запустите Desk. Убедитесь, что статусы обновляются
   и вход/регистрация в мини-аппе работают. Новая панель **не обрабатывает** старую
   `pending-reservations`: неподтверждённых старых заявок оставаться не должно.
5. Переоткройте Telegram-мини-апп. Новое меню появляется по `enabled=true`.
6. Приёмка сначала на одном тестовом ПК и тестовом аккаунте (список ниже).
   Если клуб не может выделить техническое окно, не включайте beta.

## Семантика

- «В течение часа»: блокировка свободного ПК после ответа агента; deadline —
  час от создания заявки. UI не объявляет ПК ожидающим до подтверждения блокировки.
- «Сегодня по времени»: только сегодня МСК; 1 час, интервал ≥15 минут,
  либо неизвестный конец. Блокировка при наступлении начала, **только если нет
  сессии**. Занят — `waiting`, сигнал администратору, проверка освобождения.
  Приход ожидается до `min(начало+1ч, конец)`; опоздание завершает бронь.
- «Как пойдёт»: для конфликтов удерживается остаток дня. Уже начавшаяся игровая
  сессия блокирует обещание этого ПК следующему гостю, пока реально не закончится.
- Конец выбранного интервала **не завершает игровую сессию**. Предоплаты нет,
  тарифы/депозит проверяет Gizmo. Положительный результат входа — наличие
  сессии нужного userId именно на нужном hostId, не недокументированный enum.
- Гость вводит шестизначный код из **панели администратора в клубе**. Код не
  выводится на клиентском ПК: документированного API для этого нет. Администратор
  сообщает код только лично пришедшему гостю. Это подтверждение через персонал,
  не геолокация и не абсолютная защита от передачи кода на расстоянии.
  Срок 3 минуты, пять попыток на код, новый код примерно каждые 150 секунд.
- `telegram_id` проверяется HMAC и сроком initData (1 час), Gizmo userId берётся
  из доверенного профиля. Ни ID аккаунта, ни «успешный вход» клиент не задаёт.
- Не более 2 активных броней на Telegram. Self check-in не переносит аккаунт с
  другого ПК: если аккаунт уже играет, требуется администратор. Для двух гостей
  нужны отдельные аккаунты; второй бронью нельзя принудительно переместить первый.
- PS5 только по телефону. Чужие административные блокировки не снимаются.

## Безопасность и восстановление

Gizmo API не предоставляет атомарный compare-and-set блокировки, владельца
блокировки или транзакцию unlock+login. Lease и журнал снижают риск, но **не дают
распределённой exactly-once гарантии**. Не меняйте вручную ПК, которым управляет
Desk, параллельно с автоматической операцией. Смена `modifiedTime`, отсутствие
этого поля, неопределённый POST или потерянный журнал переводят бронь в `attention`.
Если Gizmo не обновляет modifiedTime при ручном управлении, надёжно распознать
вмешательство нельзя — автоматический режим без организационного запрета
параллельного управления включать нельзя.

При обрыве связи агент не снимает всё подряд. Уже поставленные блокировки могут
оставаться после дедлайна до восстановления сети/ручной проверки. Никакой таймер
на сайте не гарантирует снятие блокировки при выключенной панели.

Для `attention`:
1. Найдите UUID заявки в панели и строку в `public.club_bookings`.
2. Проверьте hostId, состояние ПК, активную сессию и журнал SQLite. Не повторяйте
   login и не снимайте блокировку, пока не установлено, чья она.
3. Если реально началась нужная сессия, можно вручную перевести строку в
   `in_session` (после проверки userId/hostId). Если операции не состоялось —
   лично освободите **только подтверждённо нашу** блокировку и завершите строку:
   ```sql
   update public.club_bookings
   set status='cancelled',code_hash=null,updated_at=now(),message='Проверено администратором'
   where id='UUID-ПРОВЕРЕННОЙ-БРОНИ' and status='attention';
   ```
   Не удаляйте строку/журнал и не возвращайте её в `requested` для повторного POST.
   Это намеренно ручное восстановление, универсальной кнопки «снять всё» нет.

Откат: `update public.club_settings set enabled=false;` останавливает новые заявки,
но **не** отменяет существующие. Desk должен закончить/освободить их. До завершения
всех новых активных заявок SQL запрещает старые брони. Только после проверки ПК,
отсутствия незавершённых операций и остановки Desk запускайте старый `agent.py`.

## Приёмка перед эксплуатацией

- Свободный ПК → arrival → сигнал → holding → правильный код → реальная сессия.
- Неверный/истёкший код, 5 попыток, чужой Telegram, max 2, повторный submit.
- ПК занят в начале scheduled → сессия не прервана → сигнал → освобождение → lock.
- Отмена гостем, истечение часа, отключение сети до/после POST, рестарт с журналом.
- Чужая блокировка и ручная смена modifiedTime — ни одной автоматической разблокировки.
- «Как пойдёт» и более поздняя бронь — никаких обещаний занятого ПК/автовыхода.
- Минимальный баланс/неоплаченная сессия — не выдавать неподтверждённый успех.
- Крестик → трей → новое событие слышно; пауза 5 минут; восстановление после входа Windows.

## Обновление после ошибки Python.Runtime.Loader.Initialize

Новая сборка использует Qt WebEngine вместо Windows Forms/pythonnet. DLL
`Python.Runtime.dll` больше не участвует в запуске. На Windows CI запускается
**готовый EXE**: проверяются загрузка реального HTML, локального шрифта и вызов
Python API из JavaScript. Тест не читает `.env`, не подключается к клубу и не
запускает контроллер броней. Это не заменяет проверку работы на компьютере клуба.

Распакуйте новый архив целиком в новую папку, не смешивая старые и новые DLL.
`%LOCALAPPDATA%\1SHOT Desk\.env` и `desk.sqlite3` сохраняются — не удаляйте их.
Архив стал больше: Chromium/Qt поставляются вместе с приложением.

Qt/PySide6 — сторонние библиотеки под LGPL/GPL и другими лицензиями компонентов.
Используется onedir-сборка с отдельными заменяемыми DLL; исходники и лицензии:
https://code.qt.io/ и https://doc.qt.io/qtforpython-6/licenses.html .

## Версия и оформление

Текущая версия задаётся в `desktop/version.py`. Подпись `made tengizka` и версия
видны в нижней панели, версия — также в заголовке окна, подсказке трея и свойствах EXE.
`python -m desktop.write_metadata` обновляет JS и Windows version resource перед сборкой.

Векторные исходники и многоразмерный ICO находятся в `desktop/assets/`.
