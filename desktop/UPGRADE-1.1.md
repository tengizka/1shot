# Обновление до 1.1.0-beta

**Не удаляйте `.env`, `desk.sqlite3` и старую папку программы до успешной проверки.**
Обновление источников на GitHub не обновляет Supabase или компьютер клуба.

## Что изменилось

- Вход сейчас, без предварительной брони; вход в часовую бронь без кода.
- «Для друга»: отдельная бронь; «Разблокировать» снимает только нашу блокировку.
  Ни одного входа владельца брони на ПК друга. Друг входит сам с компьютера.
- Текущая сессия (включая вход с клиентского ПК, а не только из мини-аппа),
  баланс Gizmo, выход по запросу владельца с проверкой идентичности сессии.
- Отмена броней из панели и мини-аппа. Это не завершение игры и не выключение ПК.
- Новая панель: 30 ПК, фильтрация броней по ПК, Matrix, анимированный логотип,
  чёрная рамка окна, крестик в трей, отдельный полный выход.
- Мягкий звук по умолчанию; три мелодии, громкость, повтор 10–120 секунд,
  отключение звука, пауза на 5 минут. Системная громкость не меняется.
- Профиль: имя/фамилия, реальный логин Gizmo, email, телефон. Дата рождения
  только для чтения. Изменять профиль можно вне игровой сессии.
- Собственные брони в профиле и на карте выделяются синим.
- Аватар из подписанных Telegram-данных; если Telegram не передал фото,
  показывается инициал, а не чужая/случайная картинка.
- Запрос смены/восстановления пароля из профиля. Администратор проверяет личность,
  находит точный гостевой логин в панели и устанавливает новый пароль.
  Старый пароль не показывается. Самостоятельной смены пароля без администратора
  в этой версии нет. Аккаунты вне `GUEST_USER_GROUP_ID` изменять запрещено.

## Установка

1. Обновите исходники в `C:\1shot-source` из ветки `arena/01a0d663-1shot`.
2. В SQL Editor Supabase **один раз** выполните целиком
   `supabase/migrations/202609250007_club_sessions.sql`.
   Требуется ранее установленная миграция 006. Новая логика пока выключена:
   `flow_version=1`, старые функции броней продолжают работать.
3. Из `C:\1shot-source` загрузите функции:
   ```powershell
   npx.cmd supabase functions deploy club-bookings --project-ref zqhfvtgktbfnxcclqqny --no-verify-jwt --use-api
   npx.cmd supabase functions deploy club-desk --project-ref zqhfvtgktbfnxcclqqny --no-verify-jwt --use-api
   ```
   Существующие `club-agent`, `hosts`, `sync-hosts`, `pending-auth`, `upsert-profile`
   остаются необходимыми. Секреты прежние, новые создавать не нужно.
4. Распакуйте **весь** новый Windows-архив в отдельную папку.
5. Полностью остановите старый Desk, затем запустите новый. Не допускайте двух
   одновременно работающих панелей/старого `agent.py`.
   Если старая панель не выходит, сначала убедитесь в отсутствии выполняемых
   операций/броней и только затем завершите её процесс через Диспетчер задач.
   При активных или неопределённых операциях сначала ручная проверка в Gizmo.
6. При смене процесса lease предыдущего агента может действовать до 30 секунд.
   Подождите. В панели должны быть **оба** индикатора связи: Supabase и Gizmo.
   Сообщений об ошибке сервиса аккаунтов быть не должно.
7. В SQL Editor проверьте:
   ```sql
   select protocol, lease_until, lease_until > now() as online
   from public.club_worker where id=true;
   ```
   Ожидается `protocol=2`, `online=true`.
8. Дайте завершиться старым ожидающим броням с кодом. Уже начатую игровую сессию
   ради обновления не обрывайте. Затем включите новый сценарий:
   ```sql
   update public.club_settings set flow_version=2 where id=true;
   ```
   **Не меняйте `enabled` на false для этого обновления:** это другой переключатель
   старой системы, а не режим технического обслуживания.
9. Переоткройте мини-апп в Telegram. Проверьте на тестовом гостевом аккаунте и
   свободном тестовом ПК весь список приёмки ниже.

## Важные ограничения

- Без кода присутствия кнопкой входа можно воспользоваться удалённо. Таков
  выбранный сценарий. Авторизация Telegram и привязка к Gizmo остаются обязательными.
- Логин никогда намеренно не переносит уже играющий аккаунт с другого ПК.
  Отмена не снимает чужую или неподтверждённую блокировку.
- Для выхода Gizmo предоставляет `POST /users/{id}/logout`, а не атомарную
  операцию по sessionId. Перед POST проверяются userId, hostId, lastLogin и
  отсутствие второй сессии этого пользователя. Если данные изменились,
  команда отклоняется. Не управляйте тем же аккаунтом параллельно из Manager:
  серверного compare-and-set в документированном API нет.
- При ошибке после отправки POST повтор автоматически не выполняется.
  Запись `attention` требует проверки. Не удаляйте записи журнала для повторения.
- Данные баланса берутся из поля `balance` документированного UserBalance;
  другие поля не суммируются по предположению. Данные старше 45 секунд не выдаются
  за текущий баланс. При отсутствии данных показывается «Нет данных».
- Профиль обновляется документированным `POST /users`. Остальные поля, включая
  дату рождения, сохраняются из свежего чтения и проверяются после записи.
  Не редактируйте одновременно того же гостя через Gizmo Manager.
- Пароль не хранится в Supabase/SQLite. Оператор вводит его только в локальной
  панели, поле очищается после отправки. Применяется документированный Gizmo
  password endpoint с паролем в URL: не включайте логирование HTTP URL и защитите
  соединение доверенным TLS-сертификатом. В SQLite остаётся журнал без пароля.
- Кодовые брони v1 не меняются задним числом. Новые записи после включения имеют
  protocol=2. Старый агент не может объявить поддержку v2 после перехвата lease.

## Приёмка в клубе

1. Крестик → трей → открыть; «Завершить работу» → Да → процесс завершён.
2. Настроить/проверить звук, перезапустить — настройки сохранены.
3. Свободный ПК → «Войти сейчас» → подтверждённая сессия нужного пользователя.
4. «В течение часа» → holding → «Войти» без кода.
5. Активная сессия → «Забронировать для друга» → «Разблокировать»:
   сессия владельца на первом ПК остаётся; на втором не выполняется login.
6. Отмена из мини-аппа и панели, отмена чужой брони гостем запрещена.
7. Выйти из своей сессии; сменившаяся/другая сессия не должна завершаться.
8. Сравнить баланс с Gizmo, проверить свежесть после расхода/пополнения.
9. На тестовом пользователе изменить логин/имя, проверить неизменность DOB,
   проверить новый логин на клиентском ПК.
10. Запросить смену пароля, проверить личность, установить пароль через панель,
    проверить новый пароль. Не тестировать на рабочем аккаунте оператора.

## Откат

Не возвращайте старый агент к обслуживанию активных записей v2.
При проблеме сначала `update public.club_settings set flow_version=1 where id=true;`
(прячет новые действия), но оставьте Desk 1.1 работать до завершения/ручного
восстановления уже принятых команд и броней v2. Проверьте Gizmo, журнал и таблицы
`club_commands`/`club_bookings`. Отмена/смена флага сама по себе не завершает сессии
и не гарантирует снятие блокировок при выключенном агенте.
