# Обновление до 1.2.0-beta

GitHub Pages обновляется отдельно от Supabase и Windows. **До установки серверной части новый вход / регистрация работать не будут.** Не ограничивайтесь заменой EXE.

## Порядок (после 1.1)

1. Обновите исходники из ветки `arena/01a0d663-1shot`. Если 1.1 ещё не установлен, сначала выполните [UPGRADE-1.1.md](UPGRADE-1.1.md), включая миграции 006/007 и функции `club-desk` / `club-bookings`.
2. В SQL Editor Supabase выполните **один раз, по порядку**, целиком:
   - `supabase/migrations/202609250008_strict_booking.sql`;
   - `supabase/migrations/202609250009_auth_v2.sql`.
3. В PowerShell из `C:\1shot-source`:
   ```powershell
   npx.cmd supabase functions deploy club-auth --project-ref zqhfvtgktbfnxcclqqny --no-verify-jwt --use-api
   npx.cmd supabase functions deploy club-bookings --project-ref zqhfvtgktbfnxcclqqny --no-verify-jwt --use-api
   ```
   Существующие `TELEGRAM_BOT_TOKEN`, `AGENT_SECRET` должны быть установлены в Supabase; `AGENT_SECRET` в Desk должен совпадать. Новых секретов не требуется. Не присылайте их в чат.
4. В Gizmo должна существовать **ровно одна** группа с точным названием `18+`. Проверяйте её тарифы и разрешения! Если группы нет / две одноимённые — регистрация совершеннолетнего отклоняется, случайная группа не выбирается. Несовершеннолетние попадают в `GUEST_USER_GROUP_ID` (по умолчанию 3).
5. Полностью остановите старый Desk / старый `agent.py`, не прерывая активных операций. Распакуйте весь новый Windows-архив и запустите **1.2.0-beta**. Сохраните `%LOCALAPPDATA%\1SHOT Desk\.env` и `desk.sqlite3`. Два агента одновременно не запускайте.
6. Если новый режим 1.1 ещё не активирован, завершите его проверку и включите `flow_version=2` по инструкции 1.1. Не переключайте `enabled=false` ради обновления.
7. Переоткройте Telegram-мини-приложение. Проверьте на тестовом госте список ниже. При входе по телефону укажите тот же международный номер, который записан в Gizmo. При неоднозначном совпадении нескольких аккаунтов используйте никнейм: подбор аккаунта / паролей по очереди запрещён.

## Новое поведение

- Бронь разрешена только на **сейчас свободный** ПК, даже при выборе будущего времени. SQL проверяет свежесть кэша; агент перед физической операцией отдельно проверяет Gizmo. Абсолютной атомарности с параллельными действиями Gizmo Manager API не предоставляет; занятого игрока агент не отключает. Если к началу брони ПК занят, заявка отменяется, а не ждёт освобождения и не блокирует ПК позднее.
- На занятом ПК — только SVG и «Прости, но он занят..». Своя сессия доступна в отдельной карточке: ПК, начало, баланс, подтверждённый выход и плюс для брони другу. Это не управление чужим ПК.
- Старые активные брони не теряются за последними 30 строками истории. Отменять можно и заявки в `attention`, `checkin_pending`, `release_requested`, `in_session`; отмена брони **не означает выход из игры**. Если принадлежность блокировки нельзя доказать по журналу, агент оставляет ручную проверку, а не снимает чужой замок. Терминальные записи не требуют повторной отмены. Нативные старые резервации Gizmo этой миграцией не удаляются.
- Телефон помощи — отдельная ссылка `tel:+74955837811`; звонок открывается через системный обработчик, подтверждение зависит от телефона / Telegram.
- Регистрация требует никнейм, пароль, телефон, имя, фамилию, пол, дату рождения. Возраст вычисляется **при регистрации**, по дате клуба (Москва). С 18-летия — `18+`. Это самообъявленная дата, не проверка документа; существующим аккаунтам тарифные группы автоматически не меняются. Дата рождения в профиле остаётся только для чтения.
- Профиль / сброс пароля разрешены для обычной гостевой группы и точно найденной `18+`, не для произвольных групп. Проверка личности перед сбросом остаётся обязательной.
- Статистика: реальное персональное игровое время `stats/session`, период последние 30 дней, кэш до 10 минут. Если Gizmo не вернул однозначные данные — «Нет данных», не ноль. Общеклубные счётчики не выдаются за персональные. Траты и количество посещений пока не показываются.
- Нажатие логотипа мини-аппа / Desk запускает короткую секретную анимацию. Она не выполняет игровых или административных действий, повторный запуск во время анимации блокируется, учтён reduced motion.

## Безопасность нового входа

`club-auth` проверяет подписанный Telegram initData, выдаёт статус только владельцу. Данные заявки шифруются AES-256-GCM (отдельный контекст ключа на основе AGENT_SECRET), таблица закрыта для anon/authenticated. Claim атомарный; ciphertext удаляется из строки при выдаче агенту. Только агент расшифровывает пароль в памяти. Пароль не пишется в локальный журнал / профиль; старые очереди этим обновлением не переписываются.

Ограничение: 5 запросов / 15 минут на Telegram, один активный запрос. Просроченные pending/running после 3 минут не исполняются; очистка очереди выполняется агентом при следующем claim. Записи старше суток удаляются при claim. Если агент выключен, физическая очистка ждёт его запуска. Запросы с неопределённым результатом регистрации автоматически не повторяются. Если аккаунт создался, но связь оборвалась до сохранения профиля, попробуйте **вход с тем же никнеймом**, не повторную регистрацию. При неизвестном результате — администратор проверяет Gizmo. Gizmo API использует пароль в URL; отдельно проверьте политику access-логов самого Gizmo / прокси.

Старые `pending-auth`, `upsert-profile`, `sync-hosts` пока нужны мосту совместимости. Новая форма использует только `club-auth`. Неполные старые регистрационные заявки новый Desk отклоняет; не держите параллельно старый агент, который их принимал без обязательных полей.

## Приёмка в клубе

- Занятый ПК: нет формы брони; запрос на scheduled через API тоже отклонён.
- Отмена старой attention-брони с проверенным журналом и без него; чужая игра продолжается.
- Регистрация за день до 18-летия / в 18-летие: группы и поля в Gizmo правильные; проверьте также отображение пола в вашей версии Gizmo.
- Вход никнеймом и тем же номером телефона; неверный пароль не связывает аккаунт.
- Реальный баланс, аватар, неизменяемая дата рождения, статистика с периодом, сброс только после проверки администратора.
- Своя сессия → плюс → свободный ПК для друга; аккаунт владельца на ПК друга не запускается.
- Колёса даты на реальном iPhone/Android; нет горизонтального переключения страницы при вращении.
- Логотипы в обоих приложениях; крестик в трей и полный выход сохранены.

Автотесты не заменяют эту проверку на физических ПК. Supabase этой инструкцией автоматически не обновляется.
