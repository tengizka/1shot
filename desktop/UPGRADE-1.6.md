# 1.6.0-beta — инструменты администратора и переход через полночь

## Установка поверх 1.5.1

1. Обновить исходники этой ветки. После уже установленных 006–011 выполнить **целиком** в Supabase SQL Editor `supabase/migrations/202609250012_admin_tools.sql`.
2. Из папки исходников в CMD/PowerShell:

   ```cmd
   npx.cmd supabase functions deploy club-desk --project-ref zqhfvtgktbfnxcclqqny --no-verify-jwt --use-api
   ```

   Актуальные `club-agent` и `club-bookings` от 1.5 остаются обязательными. Для перехода с 1.4 и ниже сначала выполнить предыдущие инструкции. Миграция 012 обновляет серверную проверку даты для мини-аппа; одного обновления сайта недостаточно.
3. Полностью завершить старый Desk и распаковать **весь** архив 1.6 в новую папку. Сохранить `%LOCALAPPDATA%\1SHOT Desk\.env` и `desk.sqlite3`. Запустить только один экземпляр.
4. Переоткрыть мини-апп: в профиле `version 1.6.0`.

Без обновления Desk расширенный поиск и новые локальные полномочия не появятся: Python-логика находится внутри сборки. Переустановка с удалением настроек не нужна. GitHub push не обновляет компьютер клуба и Supabase.

## Поиск и пароль

- Поиск от двух символов по части никнейма, телефона, имени и фамилии. Пробелы, скобки и дефисы телефона нормализуются; регистр не важен. Результаты показывают ник, имя, телефон, группу и ID.
- Обязательно выбрать конкретный результат, даже если совпадение одно. После выбора аккаунт перечитывается по ID. Показываются первые 20 совпадений; если их больше, уточните запрос.
- Автопоиск запускается после паузы 350 мс. Каталог хранится только в памяти до 30 секунд, содержит только отображаемые поля и запрашивается у локального сервера, **не у Supabase**. Пароли в подсказки не передаются.
- Локальный Desk разрешает смену пароля аккаунтам всех групп, которые доступны через API `users`. Серверные права интеграционной учётной записи никто не обходит: если сам Gizmo запрещает действие, оно не выполнится.
- Всегда требуется подтверждение личности. Для групп, не определённых как «Клиенты» или «18+», дополнительно требуется подтверждение служебного/неподтверждённого гостевого аккаунта. Неизвестная группа не объявляется оператором, но также требует подтверждения.
- Пароль повторно проверяется после изменения. На аккаунте не должно быть активной игровой сессии. При неизвестном результате нельзя повторять смену вслепую.
- Для заявки на пароль аккаунт выбирается по авторитетному ID заявки; результат продолжает синхронизироваться с мини-аппом.

Это полномочия **локального Desk**, доступного персоналу на административном компьютере. Приложение не вводит отдельную систему аутентификации сотрудников: защищайте Windows-сессию от посетителей. Удалённое редактирование профиля в мини-аппе не получило расширенных прав. Операторские аккаунты ОС и другие системы вне API `users` не затрагиваются.

## Ручной вход

Карта зала → выбрать ПК → «Войти на выбранный ПК» → поиск аккаунта → выбрать вариант → подтвердить вход. Для служебной группы нужно отдельное подтверждение.

Вход разрешён на свободный ПК без конфликтующей брони либо по **собственной ручной брони**, которая уже ждёт гостя (`holding`). Для такой брони сначала выбирается аккаунт, затем агент снимает только доказанно свою блокировку и выполняет вход. Чужие/неподтверждённые блокировки не снимаются. По брони из мини-аппа вход владельца остаётся в мини-аппе.

На свободном ПК используется прямой вход без lock/unlock. На занятом ПК — отказ, без завершения чужой игры. Аккаунт, играющий на другом ПК, не переносится. Команда проходит через серверную очередь и существующий журнал контроллера; неизвестный login POST не повторяется. API Gizmo по-прежнему не обеспечивает атомарный compare-and-login.

## Ручные брони

«Брони» → **плюсик** → свободный ПК → время прихода → создать.

- Аккаунт и Telegram не обязательны, имя гостя необязательно.
- Быстрые кнопки: **+15 минут, +30 минут, +1 час, +2 часа**. Результат округляется вверх до сетки 5 минут и явно показывается перед отправкой.
- Можно вручную выбрать дату и время по Москве: сегодня или завтра. При времени прихода 00:00 показывается соответствующая дата/«Завтра».
- Ожидание — **30 минут после времени прихода**, не лимит игры. Блокировка свободного ПК ставится при наступлении времени брони, не заранее. Если к этому моменту ПК занят, игра не прерывается.
- Нельзя создавать новую бронь на сейчас занятый/неисправный/устаревший ПК. Пересечения с существующими бронями запрещены на сервере.
- Ручная бронь без Telegram не назначается посетителю по одному имени и не выдаётся в его списке броней. Она управляется из Desk. После фактического входа связанный с аккаунтом посетитель увидит свою сессию по обычному механизму.
- Отмена не завершает игру. Старые/неподтверждённые блокировки требуют ручной сверки, а не удаления SQLite.

## Мини-апп и сутки

В выборе «Ко времени» показывается ближайшее будущее вхождение выбранных часов/минут. Например, вечером выбор **00:00 → «Завтра, 00:00 МСК»**, включая переход месяца и года. На сервере разрешены сегодня и завтра, сетка 5 минут и ожидание 30 минут.

Если выбранное время уже прошло, пока окно было открыто, отправка требует выбрать новое время — не переносит бронь молча ещё на сутки. Часовой пояс телефона/Windows не используется для расчёта клубного времени.

## Приёмка

Проверить тестовые аккаунты разных групп, совпадающие телефоны, поиск части фамилии и смену группы между выбором и отправкой. Не начинать с единственной рабочей учётной записи администратора.

Проверить свободный/занятый ПК, отказ переносу активного аккаунта, ручную бронь без имени, конфликт интервалов, повтор отправки с тем же ID, вход по собственной ручной броне и безопасную отмену. Отдельно проверить 23:55 → 00:00 следующего дня и ожидание до 00:30 в обоих приложениях.

Автотесты используют заглушки и локальный PostgreSQL-движок; фактические права вашей интеграционной учётной записи, нагрузка большого каталога пользователей и живые ПК требуют проверки в клубе.

Пятисекундный опрос 1.5.1 сохранён, как и его расход квоты: один Desk 24/7 уже превышает 500 тысяч фоновых вызовов за 30 дней. Архивы данных, журналы и история не удалялись.
