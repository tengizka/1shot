# Брони мини‑аппа в Gizmo

Гость выбирает ПК, начало и окончание. Расписание включает ручные брони Gizmo Manager. Мини‑апп показывает ближайший занятый интервал, умеет сократить бронь до его начала и подсвечивает подходящие ПК на тот же интервал. Desk передаёт заявку в Gizmo с привязкой к аккаунту гостя и к внутреннему ID ПК. Гость входит через Gizmo Client. Для новой брони Desk не выдаёт код, не вызывает принудительный вход, блокировку или завершение сессии. Карта не передаёт данные владельцев броней.

## Правила нового режима

- Начало можно выбрать в ближайшие 24 часа с шагом пять минут, окончание — через 30 минут–6 часов. При сокращении до ближайшей брони время округляется вниз до полной минуты. Время и границы суток московские, в API передаются абсолютные даты.
- Начало интервала включается, окончание исключается. Например, при ручной брони 18:00–20:00 можно оформить 16:00–18:00 или 20:00–21:00, если ПК доступен.
- Один активный заказ мини‑аппа на аккаунт Gizmo. Чтобы сменить ПК после принятия заявки, гость отменяет бронь и дожидается результата. Из Gizmo дополнительно проверяется пересечение броней по аккаунту, включая брони на других ПК.
- Оформляем бронь на конкретное время. Баланс, тариф и оплата сессии остаются в Gizmo. PS5 бронируется по телефону.
- Бронь гостя можно отменить из приложения до начала, после начала — через администратора. Отмена из приложения меняет только подтверждённую бронь Gizmo этого гостя. Новая заявка и отмена могут некоторое время отображаться в процессе обработки.

## Сценарии и ожидаемое поведение

| Ситуация | Что происходит |
| --- | --- |
| ПК свободен сейчас, ближайшая бронь в 18:00 | В карточке показаны «Свободен до 18:00» и границы следующей брони. На карте по времени этот ПК доступен только для подходящего полного интервала. |
| Выбрано 16:00–19:00, а в 18:00 начинается бронь | Оформление заблокировано. Можно оставить этот ПК до 18:00 или открыть карту на 16:00–19:00. При переходе на другой ПК время сохраняется. |
| До следующей брони меньше 30 минут либо начало попало внутрь занятого периода | Укоротить бронь нельзя. Остаётся выбрать другой ПК или изменить время. |
| Несколько ручных броней, групповая бронь, смежные интервалы | Каждый ПК из групповой брони проверяется отдельно. Для выбранного времени проверяются все пересечения, включая бронь, начинающуюся после первого видимого интервала. Смежные интервалы допустимы. |
| ПК занят сейчас, но игровое время заканчивается раньше выбранного старта | Показан ориентир освобождения. Будущий слот можно выбрать, если ориентир ещё актуален и в расписании нет пересечения. |
| Игрок пополнил баланс или остался играть дольше | Ориентир может измениться. Мини‑апп не завершает игру. Поведение на старте брони зависит от настроек реального Gizmo. Продление сессии и работу администратора проверяем до включения. |
| Прогноза освобождения нет, он истёк, ПК отключён, вручную заблокирован или пропал из Gizmo | Место недоступно для онлайн-брони до получения свежих данных. Если в расписании есть неразбираемая действующая запись или выдача неполная, весь календарь перестаёт использоваться для записи броней. Состояние блокировки Gizmo клиентской части не интерпретируется как гарантированно снимаемое к заданному часу. |
| День закончился, выбран интервал через полночь или часовой пояс телефона другой | В полях видны даты и время Москвы. При смене суток выбранный абсолютный интервал сохраняется. Уже прошедшее время не отправляется. |
| Два гостя одновременно нажали «Забронировать» | База сериализует заявки мини‑аппа. Первая учитывается в расписании до завершения обработки; вторая получает предложение выбрать другое время или ПК. |
| Администратор добавил бронь после того, как гость открыл карточку | Перед записью агент заново читает Gizmo и отказывает при конфликте. После отказа гостю остаются выбранные даты, карту можно обновить. |
| Ручную бронь создали между последним чтением и записью | После записи агент повторно читает календарь. При обнаруженном пересечении заявку оставляет на ручную сверку. Если Gizmo сам не запрещает накладки, остаётся гонка с записью после последней проверки. Без проверки атомарного запрета накладок выпускать режим для всего клуба рискованно. |
| Двойной тап, ответ сервера потерялся, мини‑апп перезапустился | Повтор с тем же ID возвращает ту же заявку. Активная заявка также блокирует создание другой с того же аккаунта, включая вход с другого устройства. |
| Gizmo принял запись, но потерялся ответ, проверка вернула другие даты или привязка гостя не прошла | Гостю показывается необходимость сверки, а интервал остаётся зарезервированным в приложении. Агент не отправляет повторный PUT и не откатывает запись вслепую. |
| Пропало соединение с Gizmo или Desk перезапустился | Просроченный календарь выключает подтверждение на карте. Заявка, которую агент не забрал за две минуты, истекает. Зависший запрос на запись или отмену после восстановления попадает на сверку. Новый процесс его повторно не выполняет. |
| Сменился аккаунт гостя, отсутствует или удалён профиль Gizmo | Заявки прежнего аккаунта не видны через новый аккаунт. Для создания агент сверяет аккаунт с Gizmo. Ручную помощь оказывает администратор. |
| Отмена до передачи заявки в Gizmo | Она сразу снимается из очереди; запись в Gizmo не создаётся. Пока агент уже создаёт запись, отмену можно повторить после подтверждения. |
| Отмена подтверждённой брони | Агент сверяет идентификатор, аккаунт, ПК и даты, меняет статус, затем проверяет его чтением. Интервал освобождается после подтверждения отмены и обновления расписания. |
| В Gizmo Manager вручную отменили бронь | При следующей сверке Desk проверяет статус по ID. Подтверждённая ручная отмена отображается в мини‑аппе. Если запись исчезла, её перенесли или у неё изменился состав, гость получает статус «Уточните бронь у администратора». |
| Гость не пришёл, пришёл рано или после начала | Правила входа, освобождения, допуска и экран ПК определяет Gizmo. После окончания интервала приложение больше его не держит. Досрочное снятие за неявку нужно проверить и настроить в клубе. |
| Вход без кода, чужой аккаунт и экран ПК | Код у новых броней отсутствует. Показ имени в Manager, подсказка на клиенте, вход владельца и отказ чужому аккаунту проверяются на клубной версии Gizmo. |
| Старый мини‑апп, попытка оформить бронь из Desk, старый агент или бот | В режимах `drain` и `gizmo` создание записей старого бронирования блокируется в базе, включая прямой вход, если Desk проводит его через старую заявку. Ручные брони и административный вход выполняются в Gizmo Manager. Старые записи могут закончиться или отмениться привычным способом. |
| Клиент не доверяет времени телефона, выходит из приложения и возвращается | Календарь использует серверное время и ограниченный срок снимка. При возвращении приложение просит свежие данные. Запись дополнительно проверяется на сервере. |

## Проверка на клубной установке

Спецификация Gizmo описывает API, но не расшифровывает два статуса бронирования (0 и 1) и единицы Duration. Значения нужно подтвердить на вашей версии.

1. На тестовом ПК в Gizmo Manager создать короткую контрольную бронь и прочитать её через API. Сравнить `date`, `endDate`, `duration`, `status`, `hosts` и `users`. Отменить в Manager, прочитать заново и проверить, что `GET /reservations?Status=...` отдаёт только действующие брони. Проверить, что `Skip` сдвигает выдачу, а действующая бронь с началом в прошлом остаётся видна.
2. Настроить в Desk `GIZMO_RESERVATION_ACTIVE_STATUS` и `GIZMO_RESERVATION_UNIT_SECONDS` по контрольным данным. Учётной записи Desk нужны права читать ПК, сессии, пользователей и брони, создавать бронь, добавлять гостя и менять статус. Сверить часы Windows и Gizmo. Если `CLUB_API_URL` указывает на промежуточный сервер, проверить, что он передаёт параметр `action: native_bookings` в запросах к `club-desk`.
3. На тестовом контуре создать бронь из мини‑аппа и сверить в Manager имя или логин гостя, номер ПК и время. Убедиться, что ручные и групповые брони появляются в расписании. Проверить при двух одновременных операциях, запрещает ли Gizmo пересекающиеся записи каждого типа.
4. На тестовом ПК проверить сообщение на экране и вход: до защитного интервала, непосредственно до старта, при старте под чужим и своим аккаунтом, при существующей игровой сессии, после отмены, при неявке и по окончании. Проверить настройки `enableLoginBlock`, `loginBlockTime`, `enableLoginUnblock`, `loginUnblockTime`. Стык интервалов проверить с двумя разными аккаунтами. Подтвердить, что игра не прерывается неожиданно и гость с бронью может начать сессию без кода.
5. Проверить отмену из обоих интерфейсов и перенос в Manager. Повторить потерю связи при оформлении и отмене, сверить результат в Manager и состояние мини‑аппа.

## Переключение и возврат

Применить миграцию и обновить Edge Functions `club-bookings` и `club-desk`, Mini App и Desk. По умолчанию остаётся `booking_backend='desk'`. Новый Desk пересылает расписание в режиме `drain` или `gizmo`. Режим действует на весь клуб, проверку отдельного ПК проводят до переключения всего клуба.

```sql
update public.club_settings set booking_backend='drain' where id;
-- Дождаться завершения старых броней и проверить, что прежний агент не обрабатывает заявку.
-- Свежий снимок Gizmo обязателен для следующей команды.
update public.club_settings set booking_backend='gizmo' where id;
```

Для возврата перейти в `drain`, отменить или дождаться завершения новых заявок и сверить нативные брони, включая ручные, в Gizmo Manager. Старый Desk не учитывает нативное расписание при создании блокировок, поэтому перед возвратом проверить отсутствие пересекающихся оставшихся броней. После сверки установить `desk`.

### Ручная сверка

Если в Desk есть сообщение о ручной сверке, оператор с доступом к БД может открыть список неопределённых заявок. Эти данные предназначены для работы внутри клуба.

```sql
select id, gizmo_id, host_id, gizmo_user_id, starts_at, ends_at, message
from public.club_native_bookings
where status = 'review'
order by changed_at;
```

Найти запись в Gizmo по `gizmo_id` или заметке `1SHOT app request=<id>`. Если запись существует, сверить ПК, владельца, даты и пересечения. После подтверждения оставить её и перевести конкретную заявку в `confirmed` с правильным `gizmo_id`. Если записи нет или администратор отменил её в Gizmo и проверил результат, перевести конкретную заявку в `cancelled`. При корректировке строки указать `changed_at=now()` и очистить `message`. Не освобождать интервал в базе, пока в Gizmo существует требующая разбора запись.
