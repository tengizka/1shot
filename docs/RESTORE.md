# Если Supabase сломался: переезд на новый сервер

Всё, что нужно, лежит в двух местах:

- **В репозитории** (не секретно): структура базы `supabase/backup/schema.sql`, код всех серверных функций `supabase/functions/`, скрипт переезда `scripts/restore-supabase.sh`.
- **У Тенгиза лично** (секретно, в репозиторий не класть): `data.sql` — все данные (гости, брони, промокоды, меню). Свежую копию снимает Claude по просьбе «сделай бэкап базы».

## Переезд за 5 минут

1. Создать новый проект на supabase.com (регион любой, лучше Европа).
2. Скопировать оттуда: **id проекта** (кусок адреса `https://<id>.supabase.co`) и **строку подключения к базе** (Project Settings → Database → Connection string → URI, вставить пароль).
3. На компьютере с репозиторием:
   ```
   supabase login
   scripts/restore-supabase.sh <id> "<строка подключения>" путь/к/data.sql
   ```
   Скрипт спросит токен бота и AGENT_SECRET (тот же, что в `.env` у Desk).
4. Сделать три шага, которые скрипт напишет в конце: запушить адрес мини-аппа, поменять `SUPABASE_URL` в `.env` у Desk, открыть ссылку настройки бота.

Можно и проще: написать Claude «Supabase упал, вот новый проект» и дать доступ к новому проекту — он сделает всё сам.

## Что не переносится само

- **Ключи и токены** (токен бота, AGENT_SECRET, пароль Gizmo) в бэкапе не хранятся — они у Тенгиза и в `.env` Desk.
- Данные новее последнего бэкапа: брони и анкеты, созданные после снятия `data.sql`. Gizmo (балансы, часы, аккаунты) при этом не страдает — он живёт в клубе отдельно.
