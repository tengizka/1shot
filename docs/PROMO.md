# Промокоды и лендинг

Лендинг: https://tengizka.fun/1shot/ — кнопка открывает бота @oneshotagent и передаёт промокод площадки (`?startapp=КОД`), мини-апп вставляет его в анкету.

| Площадка | Промокод | Ссылка для рекламы |
|---|---|---|
| Яндекс Поиск | `LEVELUP` | https://tengizka.fun/1shot/?p=LEVELUP |
| Яндекс Карты | `RESPAWN` | https://tengizka.fun/1shot/?p=RESPAWN |
| ВКонтакте | `HEADSHOT` | https://tengizka.fun/1shot/?p=HEADSHOT |
| Сайт без рекламы | `GG` | https://tengizka.fun/1shot/ (по умолчанию) |

Без `?p=` лендинг подставляет `GG` — гость пришёл на сайт не из рекламы.

## Регистрация на ресепшене (без Telegram)

На лендинге блок «Нет Telegram?» показывает кодовое слово площадки. В Desk: «Анкеты» → «+ Новый гость»: данные с документа, пароль вводит гость, пол и промокод выбираются кнопками («Без промокода» — без бесплатного часа), галочка «Личность проверена». Desk делает те же проверки, что и для анкеты из Telegram (дубли ника и телефона, профиль, пароль), записывает промокод на сервере (`club_promo_desk_redemption`, источник `desk`, один бесплатный час на аккаунт Gizmo) и только потом начисляет `standart 1 h`. Повторное нажатие с той же формой не создаёт второй аккаунт, а лишь доначисляет час, если не было связи.

## Как это работает

1. `club-auth` принимает `promo_code`, SQL `club_registration_submit` проверяет его по `club_promo_codes` (неизвестный или выключенный код — понятная ошибка в анкете).
2. Запись в `club_promo_redemptions` живёт дольше анкеты (анкеты чистятся через 7 дней) и повторяет её статус триггером.
3. После очного подтверждения Desk (`desktop/promo.py`) один раз заказывает гостю тайм-товар `standart 1 h`:
   - товар должен быть ровно один, стоить 0 ₽ и давать ровно 60 минут, иначе ничего не заказывается;
   - чек с ненулевой суммой останавливает начисление для ручной проверки;
   - начисление проверяется по списку времени гостя; прерванный заказ никогда не повторяется автоматически;
   - в Gizmo пишется заметка «Автоматически (1SHOT Desk): выдан 1 час STANDART за промокод КОД при регистрации».
4. Способ оплаты для заказа за 0 ₽ — `PROMO_PAYMENT_METHOD_ID` в `.env` Desk (по умолчанию `-1`, «Наличные»). Перед запуском рекламы проверить одной тестовой регистрацией.

## Новый промокод

```sql
insert into club_promo_codes(code,channel) values('NEWCODE','Название площадки');
-- выключить: update club_promo_codes set active=false where code='NEWCODE';
```

## Метрика

В `index.html` впиши номер счётчика в `window.YM_ID`; клики по кнопке уходят в цель `open_bot` с параметром `code`.

## Статистика и обзвон

`analytics/Get-Analytics.ps1` на ПК клуба (берёт `.env` Desk) теперь добавляет в `1SHOT_Statistika_Club.xlsx`:

- **Промокоды** — по каждой площадке: анкет, подтвердили в клубе, ждут, отклонено/истекло, час выдан, пришли повторно (играли в 2+ разных дня после подтверждения), потратили после бесплатного часа, в среднем на гостя и цена нового гостя. Бюджеты вписываются в `PROMO_BUDGET` в начале `Export-ClubAnalytics.py`.
- **Гости по промокодам** — каждый подтверждённый гость: код, ник, дата, выдан ли час, дни с визитами, последний визит, траты.
- **Обзвон спящих** — постоянники, которых не было больше 3 недель, отсортированы по потерянному доходу; готовая фраза про подарочный час и пустые колонки «Позвонили» и «Результат». Таблица пересобирается при каждом запуске, поэтому отметки девчонок лучше вести в копии файла.

Траты считаются только через аккаунт гостя (время и товары, пробитые на него); бар, проданный обычной продажей, сюда не попадает. Данные с сервера берутся через `club-desk` → `promo_report` (только коды и статусы, без телефонов и Telegram).
