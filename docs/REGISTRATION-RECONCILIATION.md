# Сверка спорной регистрации и подготовка обновления

Статус: реализация в исходниках, миграция 015 НЕ применена к рабочему клубу. Новая форма остаётся staged. Это не объявление готовности всего выпуска.

## Сверка через вход самого гостя

В Desk у заявки `attention` появляются «Проверить вход гостя» и отдельное «Завершить сверку». Администратор не вводит, не выбирает и не видит пароль. Гость сам выполняет обычный вход в мини-аппе; игровую сессию завершать не нужно.

Для завершения требуются одновременно:

- Успешный вход того же Telegram после перехода заявки в attention, не старше 10 минут; незавершённые запросы и старые legacy-записи не подходят.
- Текущая связь профиля именно с подтверждённым UID. Если известен созданный UID (в облаке или локальном журнале), другой аккаунт не принимается.
- Повторная проверка реального профиля Gizmo: ник, имя, фамилия, телефон, дата рождения, пол, гостевая возрастная группа; удалённый/отключённый аккаунт не принимается.
- Отдельная отметка очной проверки и подтверждение конкретного отображённого аккаунта.
- Живая lease доверенного Desk и серверная повторная проверка доказательства входа непосредственно в транзакции завершения.

SQL не создаёт и не заменяет связь профиля, не пишет в Gizmo, не меняет пароль. Он только переводит спорную заявку в done, очищает анкету и одноразово фиксирует доказательство. Повтор того же завершения идемпотентен. Аудит содержит ID заявки/доказательства/аккаунта/worker и время, но не пароль или анкету; пока сохраняется без автоматического удаления.

При смене входа между просмотром и подтверждением требуется новый просмотр. При потере ответа можно повторить отправку того же подтверждения: создание аккаунта и смена пароля не выполняются. Новый worker после перезапуска не может выдавать себя за старого владельца claim; 403/409 при отправке старого исхода останавливают автоматические повторы. После перевода заявки в attention используется свежий вход гостя и сверка новым живым Desk.

### Что не «исправляется» этой кнопкой

Если аккаунт не появился, пароль не был установлен или гость не может войти, эта процедура **не разблокирует повторное создание**. Такие случаи остаются заблокированными до отдельного безопасного решения: в частности, выдачи разрешения на самостоятельную установку пароля гостем. Теперь реализован для известного UID отдельным разрешением 016; см. GUEST-PASSWORD-GRANTS.md. В рабочем клубе он ещё не включён. Не удалять локальный журнал, не придумывать UID и не менять статус напрямую ради повтора.

Несовпадение группы/профиля также не обходится дополнительной галочкой. Проверка реальной политики Gizmo всё ещё обязательна.

## PowerShell preflight — без установки

`release/registration/Prepare-Upgrade.ps1` выполняет только подготовку:

1. Проверяет Windows, наличие настроек и базы, отсутствие распознаваемых Desk/legacy-agent процессов. X скрывает Desk в трей: нужен полный выход. Сам сценарий процессы не убивает.
2. Создаёт новую папку вне репозитория, закрывает наследование ACL и разрешает доступ текущему пользователю и SYSTEM до копирования секретов.
3. Сохраняет все локальные файлы настроек; SQLite копируется Backup API с включением зафиксированных WAL-записей, integrity_check и переводом копии в самостоятельный файл без WAL-зависимости. Оригинал не меняется. Ссылки/junctions и изменяющиеся во время копирования обычные файлы отклоняются.
4. Проверяет SHA-256 каждого файла. Manifest содержит пути, размеры, хэши, но не значения секретов. Копия .env остаётся секретом и не предназначена для загрузки в чат/GitHub.
5. Создаёт план с хэшами миграций 014/015/016, всегда с `apply_allowed: false`. Уже существующая папка не перезаписывается. Неуспешная копия не удаляется автоматически и не считается пригодной.

Необязательный `-CheckSupabase` запрашивает personal token скрыто и выполняет фиксированный SELECT через Management API. Он не читает анкеты/пароли, проверяет признаки схемы, живую lease и pending auth. Наличие 014/015 без проверенной истории останавливает подготовку: существование объекта не доказывает контрольную сумму миграции. Токен не записывается в план/копию и ошибки ответов не печатаются.

Режим по умолчанию использует установленный Python. Новый упакованный Desk умеет `--backup-local` без запуска интерфейса и подключений; для `-BackupExecutable` нужен новый staged EXE с проверяемым `backup-capabilities.json`. Старый EXE без этого файла не запускается как утилита. Эта пара файлов не является цифровой подписью: будущий downloader обязан проверять доверенный хэш всего релизного архива.

**Preflight не заменяет** резервную копию облачной БД, журнал применённых миграций, автоматическую безопасную остановку всех экземпляров на других компьютерах, согласованное развёртывание функций/Desk и включение формы. Полный единый updater ещё не готов. `-AllLegacyWorkersStopped` фиксирует заявление оператора, а не автоматически доказывает отсутствие процессов на других машинах. План нельзя использовать как разрешение применить SQL вручную.

## Проверки

Локально: 110 Python-тестов и 36 Deno/SQL/server-тестов. Проверены свежесть/владелец/UID доказательства, отказ на старом login, подтверждение, конфликт связи, одноразовость/идемпотентность, отсутствие записей Gizmo, копия активного WAL, отказ на существующей папке и обнаружение повреждения копии. Браузер проверяет новый просмотр/подтверждение и отсутствие поля пароля. Windows CI проверяет preflight с Python и с реальным упакованным headless EXE; актуальный результат относится к коммиту в CI, не к живому клубу.
