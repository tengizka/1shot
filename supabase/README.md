# Восстановление статусов зала

Проверенный ответ рабочего `/functions/v1/hosts`: `{"hosts":[]}`.
Это не медленный рендер. Причина может быть в пустой `hosts_cache` или в RLS,
который скрывает строки от SUPABASE_ANON_KEY в прежней функции.

## Обязательный серверный шаг (GitHub Pages этого НЕ делает)

В Supabase → Edge Functions → hosts замените код на `functions/hosts/index.ts`
и разверните функцию. Отключите проверку JWT для этой публичной функции списка ПК.
С CLI в связанном проекте: `supabase functions deploy hosts`.
Конфигурация `config.toml` содержит verify_jwt=false.
SUPABASE_SERVICE_ROLE_KEY доступен только в окружении Edge Function; не копируйте его в HTML.

Проверка в SQL Editor (ничего не изменяет):

```sql
select count(*) from public.hosts_cache;
select host_id, zone, status, updated_at
from public.hosts_cache order by updated_at desc limit 40;
```

- Строки есть, API до обновления был пуст: вероятная причина — права anon/RLS.
- Строк нет: запустите обновлённый `agent.py` на компьютере с Gizmo.
  Нужен лог `Синхронизировано хостов: N` с N > 0.
  Если sync-hosts возвращает 401/403, проверьте gateway JWT функции sync-hosts
  и соответствие AGENT_SECRET. Не отправляйте секреты в переписку.
- Строки старше 30 секунд: агент не обновляет кэш. Пунктирные мониторы —
  честный статус «нет связи», не «свободен» и не «сломан».
- Если ошибка Gizmo: проверьте доступность локального IP с машины агента.

Агент не запускается внутри Telegram. Он должен работать постоянно на машине клуба.

## Что опубликованный интерфейс уже умеет

Карта 31 места (30 ПК и PS5) из присланного изображения загружается независимо
от API. VIP/STANDARD подсвечивают соответствующие места, повторное нажатие
возвращает весь зал. Свободные места доступны только при свежем updated_at.
Дополнительные номера из Gizmo выводятся текстом — координаты не выдумываются.
В новой карте нет случайных/демонстрационных статусов.

Бронирование отправляет initData и duration_minutes=60, как требует предоставленная
функция reservations. Агент читает telegram_user_id/start_time из предоставленной
очереди и передаёт Gizmo окончание через 60 минут от заявки.

После установки миграции 202609250003 и новой функции reservations лимит двух
активных броней проверяется атомарно в БД. Автоснятие нативной брони по endTime
нужно проверить на версии Gizmo клуба; ручные блокировки агент не снимает.
Очередь pending-reservations предполагает один экземпляр агента. В агенте v3 повторная отправка той же заявки блокируется локальным журналом (см. текущую инструкцию).

## Ошибка duration_minutes (скрин пользователя)

В SQL Editor выполните `migrations/202609250002_reservation_duration.sql`.
Миграция добавляет отсутствующий integer-столбец duration_minutes с default 60
и обновляет schema cache PostgREST. Существующие строки получат значение 60,
так как продукт предполагает часовые брони. Если исторические брони имели другую
длительность, перед выполнением миграции сохраните их и согласуйте перенос данных.
Миграция не исправляет возможные другие несовпадения неизвестной схемы таблицы.
После выполнения проверьте новую заявку и лог агента. Обновите локальный agent.py:
теперь он принимает как числовой result Gizmo, так и объект с id.

## Баланс

В прежнем HTML сумма всегда заменялась на «—». Теперь числовой profile.balance,
если он приходит при авторизации, отображается (включая нулевой баланс). Это
снимок при входе, не онлайн-синхронизация. Если сервер суммы не передаёт,
показывается «Нет данных», а не выдуманный ноль.
Для живого баланса нужен контракт API Gizmo для суммы/депозита и безопасная
серверная выдача профиля. Этих данных в предоставленном коде нет. Не отправляйте
пароли или секреты; нужен код auth-status/upsert-profile и описание полей ответа
Gizmo для баланса с обезличенным примером.

## Звонки и эффекты

Кнопка клуба открывает окно с обычной tel-ссылкой и копированием номера.
В Telegram Desktop наличие приложения для tel-ссылок зависит от ОС; сайт
не может принудительно инициировать звонок. Номер можно скопировать вручную.
Матрица не перехватывает касания, при скрытии страницы останавливается,
при prefers-reduced-motion отключается. Карта по умолчанию увеличена,
поддерживает прокрутку, +/−, обзор всего зала и фокус на зоне VIP/STANDARD.

## Согласование с реальной схемой (скрин 25 сентября)

У таблицы обязательны telegram_id, host_id, duration_hours, price. Есть created_at.
Прежняя функция использовала чужую схему (telegram_user_id, telegram_username,
start_time). Добавление duration_minutes решало только первую ошибку.

Порядок обновления:
1. SQL Editor: выполнить `migrations/202609250003_reserve_existing_schema.sql`.
   Она создаёт SQL-функцию, не меняет существующие столбцы и записи.
2. Заменить и Deploy код Edge Function `reservations` из одноимённой папки.
3. Заменить и Deploy код Edge Function `pending-reservations`.
4. Для обеих функций gateway Verify JWT отключён: reservations проверяет подпись
   Telegram и срок initData, pending-reservations проверяет x-agent-secret.
5. Заменить локальный agent.py и перезапустить ОДИН экземпляр.

Новая запись: telegram_id из подписанного Telegram, duration_hours=1, price=0
(только бронь, не покупка времени), start берётся из created_at. Очередь не пишет
неподтверждённый столбец processed_at. Уже добавленный duration_minutes можно
оставить, новая функция его не использует.

Таймауты Supabase у агента: подключение 5с, чтение 15с. Запрос pending-auth при
таймауте повторяется обычным следующим циклом; POST в Gizmo автоматически не
повторяется. Это смягчает медленные ответы, но не исправляет сетевые сбои.
Если предупреждения постоянные, нужны логи Edge Function pending-auth и проверка
сети на компьютере клуба. Все три типа задач пока выполняются последовательно;
долгий auth-запрос может задержать синхронизацию хостов.

## Внешний ключ users_map → profiles (подтверждён скрином)

upsert-profile записывает аккаунт в profiles, тогда как старый FK брони требовал
наличия того же telegram_id в users_map. Теперь profiles является источником
идентичности для reservations; остальные ссылки на users_map не меняются.

1. Сохраните резервную копию БД. Выполните в SQL Editor
   `migrations/202609250004_reservations_profile_fk.sql` **целиком**.
2. Убедитесь, что результат содержит `REFERENCES profiles(telegram_id)`.
3. Установите обновлённый agent.py. Он больше не сообщает done после неуспешного
   сохранения профиля (HTTP 500 и отсутствие ok:true считаются ошибками).
4. Выйдите из аккаунта в мини-аппе и войдите повторно для сохранения профиля.
5. Проверьте одну бронь. Удалять таблицу users_map или ограничения вручную не нужно.

Функция upsert-profile из предоставленного кода совместима с агентом. В репозитории
есть дополнительно усиленная версия: проверка обязательного секрета, типов ID и
только авторизация через заголовок. Её можно Deploy отдельно с Verify JWT выключенным;
проверка x-agent-secret остаётся включённой. Это не обязательно для исправления FK.

Если SQL остановился на `Migration stopped`, он не удалил записи и не заменил
старый FK. Для диагностики выполните локально в SQL Editor (это идентификаторы
пользователей; не публикуйте результат открыто):

```sql
select r.telegram_id, count(*) as reservation_count
from public.reservations r
left join public.profiles p on p.telegram_id = r.telegram_id
where p.telegram_id is null
group by r.telegram_id;
```

Не создавайте фиктивные профили и не удаляйте старые брони. Для переноса отсутствующих
профилей нужно проверить реальную схему users_map и подтверждённую привязку к Gizmo.

## Gizmo отклоняет POST /reservations с HTTP 400

Это этап после успешного получения заявки агентом. Точная причина находится в
теле ответа Gizmo, а не в предупреждении Python об utcnow(). Агент теперь
использует timezone-aware UTC и включает в ошибку до 2000 символов ответа Gizmo,
скрывая настроенные пароль, секрет агента и заголовок авторизации. Тело запроса
и заголовки не логируются. Время окончания по-прежнему created_at + 60 минут.

После обновления агента выполните одну новую тестовую бронь и посмотрите строку
`Gizmo POST /reservations HTTP 400: ...`. Старую failed-заявку агент не повторяет.
Если ответ пустой, требуется схема POST /reservations из Swagger установленной
версии Gizmo. Нельзя угадывать обязательные поля или считать HTTP 400 успехом.
